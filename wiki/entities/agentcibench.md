# AgentCIBench

An evaluation harness for whether computer-use agents make context-appropriate disclosure decisions, introduced in [[goel-2026-capable-but-careless]] (Goel & Gurevych, EMNLP 2026). Code at `github.com/UKPLab/emnlp2026-agentcibench`, data at `hf.co/datasets/UKPLab/AgentCIBench`.

![[Pasted image 20261112130140.png]]
## At a glance

- **Unit:** a scenario = app state + task prompt + recipient + must-share items + must-not-share items. The agent's one externally visible action is scored.
- **Metrics:** utility, leakage, refusal, and engagement-conditioned leakage `L_eng = L / (1 − R)` (primary).
- **Failure modes:** visual co-location, task-ambiguity overshare, recipient misalignment (see [[privacy-leakage-in-agents#Failure modes]]).
- **Pool:** 117 scenarios (75 TAO, 18 VCL, 24 RMA), generated by MCTS mutation of everyday seed requests. The generator, not the fixed pool, is the main released artifact, so the pool can be regenerated as models change.
- **Environment:** OpenApps on BrowserGym (six apps). Two tracks: state-grounded (structured text in, action JSON out) and end-to-end UI.
- **Scoring:** deterministic matcher + LLM judge, with reported human agreement κ = 0.89.

## Headline findings

- Across 15 agents: mean utility 68.8%, mean leakage 67.9%; L_eng ranges from 14.0 (Claude-Opus-4.7) to 98.3 (Gemini-3.1-Pro).
- Prompt-only defenses cut L_eng by roughly 33–36 points while raising utility. See [[prompt-defenses-for-contextual-privacy]].

## Caveats

- The source paper calls the pool an adversarial stress test: read rates as relative orderings.
- Memory and multi-turn personalization are out of scope (contrast [[cimemories]] and [[privacy-leakage-in-llm-memory]]).
- The paper has several internal numeric inconsistencies; see the caution callout on [[goel-2026-capable-but-careless]].
